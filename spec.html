Agent payment spec

An invoice is fully described by its URL fragment: #c=base|arbitrum&to=0x…&amt=12.5&memo=…&from=<block>&tx=<optional hash>. No server stores anything.

Steps for an agent

  1. Parse the fragment (or the JSON shown on the pay page). Amount atomic = amt × 106 (USDC has 6 decimals).
  2. Send a transaction to the USDC contract with the provided calldata (transfer(payTo, amountAtomic)).
  3. Verify: eth_getTransactionReceipt → status 0x1 and a log from the USDC contract with topic0 = Transfer, topic2 = payTo (padded), data = amountAtomic, block ≥ from.
  4. Present proof by appending &tx=0x… to the invoice URL.

USDC contracts (native, Circle)

  • Base (8453): 0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913
  • Arbitrum One (42161): 0xaf88d065e77c8cC2239327C5EDb3A432268e5831

The JSON mirrors the shape of an HTTP 402 / x402 "payment required" body, but this is a static site: it cannot return a real 402 status code. A server can embed the same JSON in a real 402 response.
